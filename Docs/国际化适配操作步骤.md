# 国际化适配操作步骤

> 按顺序执行即可完成一个项目的多语言适配。每一步的原理和踩坑细节见《[iOS 国际化适配指南](iOS国际化适配指南.md)》。

## 第 0 步：确定方案

动手前先定下四件事：

| 事项 | 本项目的选择 |
| --- | --- |
| 支持哪些语言 | zh-Hans、en、ar、de、ja、ru |
| 开发语言（源语言） | zh-Hans |
| 兜底语言（用户的语言都不支持时显示） | en |
| 切换方式 | App 内即时切换，同时提供跳转系统设置的入口 |

## 第 1 步：工程配置

1. **Project → Info → Localizations** 中添加全部语言。
2. Build Settings 中开启 `LOCALIZATION_PREFERS_STRING_CATALOGS` 和 `SWIFT_EMIT_LOC_STRINGS`。
3. 新建 String Catalog：
   - `Localizable.xcstrings`：界面文案；
   - `InfoPlist.xcstrings`：App 名称（`CFBundleDisplayName`）和权限说明（`NS*UsageDescription`）。
4. 在 Info.plist 中为上述每个键保留**基础值**，否则翻译不生效。
5. 已有 `.strings` / `.stringsdict` 的项目：右键 → *Migrate to String Catalog*。

## 第 2 步：接入本地化框架

1. 添加 `WBLocalizationKit` 依赖（*Add Package Dependencies → Add Local…*）。
2. 启动时初始化，必须在创建任何界面之前：

   ```swift
   LocalizationManager.shared.bootstrap(fallbackLanguage: "en")
   ```

3. 切换语言后重建界面：
   - UIKit：监听 `.wbLanguageDidChange`，调用 `UIApplication.shared.relocalize { _ in 新的根控制器 }`；
   - SwiftUI：根视图加 `.localizedRoot()`。
4. 做语言设置页：列表取 `availableLanguages`，主标题用 `nativeName`；点击时调用 `setLanguage(_:)`；另外放一个 `openSystemLanguageSettings()` 入口。

## 第 3 步：文案改造

1. **找出硬编码文案**：

   ```bash
   rg '"[^"]*\p{Han}' -g '*.swift'          # 中文开发的项目
   ```

2. **建立统一入口** `L10n`，key 按「模块.页面.语义」命名：

   ```swift
   enum L10n {
       enum Home {
           // 用计算属性，不要用 static let；必须传 bundle: .localized
           static var title: String { String(localized: "home.title", bundle: .localized) }
           static func items(_ count: Int) -> String { L10n.format("home.items", count) }
       }
   }
   ```

3. 逐个替换，同时注意：
   - **禁止拼接句子**，整句作为一条文案；
   - 多个参数使用 `%1$@`、`%2$@` 位置参数；
   - 与数量有关的文案在 Catalog 中 *Vary by Plural*；
   - 每条文案写 Comment，说明使用场景和参数含义；
   - 字面量百分号写成 `%%`，或者改写措辞。
4. SwiftUI 中 `Text(变量)` 不会本地化，要传入已经翻译好的字符串。
5. 由数据拼接出来的动态 key，需要在 Catalog 中手动添加。

## 第 4 步：格式化改造

全局搜索下列写法，统一换成 `LocalizedFormatters.current`：

| 搜索 | 替换为 |
| --- | --- |
| `dateFormat =` | `date(_:template:)`；与服务端交互用 `posixDateFormatter()` |
| `"\(price)"`、`String(format: "%.2f"` | `number` / `currency(_:code:)` / `percent` |
| `joined(separator: ", ")` | `list(_:)` |
| `ByteCountFormatter` | `bytes(_:)` |
| `Locale.current` | `LocalizationContext.locale` |

UIKit 的 `UIDatePicker` 等系统控件要显式设置 `locale` 和 `calendar`。

## 第 5 步：布局改造（RTL 与长文本）

1. 约束：`left/right` → `leading/trailing`；边距使用 `directionalLayoutMargins`。
2. 文本：`.left` → `.natural`。
3. 图标：
   - 导航类箭头改用 `chevron.forward` / `arrow.forward`；
   - 自定义方向性图片在 Asset 中设置 *Direction: Left to Right*；
   - 播放键、对勾、Logo 不镜像。
4. 水平位移动画、手势判断：根据 `view.isRightToLeft` 对方向取反。
5. UIKit 横向列表：内容尺寸确定后调用 `scrollToLeadingEdge()`。
6. 手机号、验证码、金额、播放控件：强制从左到右。
7. 插入用户内容（昵称、商品名）使用 `bidiIsolated`；手机号、版本号使用 `forcedLeftToRight`。
8. 长文本：去掉固定宽度和单行限制；按钮宽度由内容决定，放不下时改为竖排；二级页面使用 inline 标题。
9. 显示中文/日文内容时，用 `AttributedString.languageIdentifier`（UIKit 用 `kCTLanguageAttributeName`）标注语言。

## 第 6 步：资源与系统文案

1. 含文字的图片：Asset → *Localize*，**每种语言都要显式标注，包括开发语言**。
2. 启动屏：只保留 Logo 和背景色，不放任何文字。
3. 在 `InfoPlist.xcstrings` 中翻译 App 名称和权限说明，App 名称尽量短。
4. 第三方 SDK：在 `.wbLanguageDidChange` 通知中调用各 SDK 的语言设置接口。

## 第 7 步：服务端协作

1. 所有请求调用 `request.setAcceptLanguage()`。
2. 服务端文案的缓存 key 中加入语言。
3. 时间用 ISO 8601 + UTC 传输，金额带币种代码，错误信息返回错误码。
4. 把用户的 App 语言上报给服务端，用于推送文案。

## 第 8 步：翻译交付

1. 导出给翻译人员：

   ```bash
   xcodebuild -exportLocalizations -project WBLocalization.xcodeproj -localizationPath ./Localizations -exportLanguage ar -exportLanguage de
   ```

2. 收回译文后导入：

   ```bash
   xcodebuild -importLocalizations -project WBLocalization.xcodeproj -localizationPath ./Localizations/ar.xcloc
   ```

3. 导入后在 Catalog 中确认没有 `New` / `Needs Review` 状态的条目。

## 第 9 步：验证

1. **自动化测试**（建议接入 CI 作为门禁）：

   ```bash
   xcodebuild test -project WBLocalization.xcodeproj -scheme WBLocalization -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
   ```

   测试会检查：翻译缺失、占位符不一致、复数类别不全、代码引用了不存在的 key、Catalog 中残留废弃 key。

2. **伪语言冒烟测试**：在 Scheme 中依次勾选 `-NSDoubleLocalizedStrings YES`（长度加倍）、强制 RTL、`-NSShowNonLocalizedStrings YES`（标出未翻译文案），把主要页面各走一遍。

3. **截图走查**：生成每种语言的截图，交给设计和翻译人员检查：

   ```bash
   Scripts/screenshots.sh "iPhone 17 Pro" build/screenshots ar de ja ru
   ```

4. **真机抽查**：至少覆盖一种 RTL 语言和一种长文本语言，包括最大字号的 Dynamic Type。

## 上线前检查清单

- [ ] 自动化测试全部通过
- [ ] 每种语言冷启动正常；App 内切换后文案、方向、格式、图片同时生效
- [ ] 杀掉 App 重启后，所选语言保持不变；在系统设置中修改语言后，以系统设置为准
- [ ] RTL 下没有方向错误的图标、动画或列表
- [ ] 长语言下没有被截断的按钮或标题
- [ ] 权限弹窗、App 名称在下次启动后与所选语言一致
- [ ] 服务端返回的内容与 App 语言一致
