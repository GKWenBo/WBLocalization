# WBLocalization 开发设计文档

> 版本：v1.0 ・ 日期：2026-10-19 ・ 依据：[spec.md](../spec.md)

## 1. 背景与目标

开发一个 iOS 国际化适配实践项目，覆盖启动屏、App 名称、权限文案、文本、复数、格式化、RTL 布局、长文本、字体排版、图片资源、双向文本、输入框等真实项目会遇到的适配点。交付三部分：

| 交付物 | 说明 |
| --- | --- |
| `WBLocalizationKit` | 本地 SPM 包，零第三方依赖，可直接用于生产项目 |
| Demo App | 功能目录式，每个适配点同时提供 SwiftUI 与 UIKit 实现，便于对照 |
| 《iOS 国际化适配指南》 | 真实项目适配流程、常见坑与解决方案、检查清单 |

### 1.1 技术约束

| 项 | 取值 |
| --- | --- |
| 语言 | Swift 5.9+（Swift 6 语言模式兼容） |
| 最低系统 | iOS 15.0 |
| 构建环境 | Xcode 27 |
| 字符串资源 | String Catalog（`.xcstrings`），构建时编译为 `.strings/.stringsdict`，iOS 15 可用 |
| 工程管理 | 手写 `.xcodeproj`（objectVersion 77，文件夹同步组），不依赖 XcodeGen/Tuist |

### 1.2 支持语言

| 语言 | 代码 | 选择理由 / 适配重点 |
| --- | --- | --- |
| 简体中文 | `zh-Hans` | 开发语言（Development Language） |
| 英语 | `en` | 基准语言、复数 one/other |
| 阿拉伯语 | `ar` | **RTL** 布局镜像、阿拉伯-印度数字、6 种复数形式（zero/one/two/few/many/other）、双向文本 |
| 德语 | `de` | **长文本**（平均比英文长 30%+）、长复合词，暴露截断/按钮撑破问题 |
| 日语 | `ja` | 字体回退（中日汉字字形差异）、语序不同（位置参数）、日本年号历法 |
| 俄语 | `ru` | **复杂复数**（one/few/many/other）、西里尔字母长度、格变化 |

## 4. WBLocalizationKit 详细设计

### 4.1 AppLanguage —— 语言模型

```swift
public enum AppLanguage: Hashable, Sendable {
    case system                 // 跟随系统（含系统设置中的 per-app 语言）
    case specific(String)       // 语言代码，如 "ar"、"zh-Hans"

    public var code: String?                       // .system 为 nil
    public var locale: Locale                      // .system 时为解析后的实际 locale
    public var nativeName: String                  // 用该语言自身书写的名称：العربية / Deutsch
    public var isRightToLeft: Bool                 // Locale.characterDirection(forLanguage:) == .rightToLeft

    /// 由 Bundle.main.localizations 自动生成，过滤 "Base"，不在代码里写死语言列表
    public static func available(in bundle: Bundle = .main) -> [AppLanguage]
}
```

### 4.2 LanguageResolver —— 匹配与回退

- 输入：用户偏好语言列表（`Locale.preferredLanguages`）+ App 支持的语言列表
- 输出：最终使用的 `.lproj` 名称
- 实现：逐个偏好语言匹配；单个偏好内先用 `Bundle.preferredLocalizations(from:forPreferences:)` 处理 `en-GB → en`、`de-AT → de`、`ar-SA → ar` 等地区回退，再按基础语言做文字变体回退（`zh-Hant-HK → zh-Hans`，可关闭）
- 实测：系统 API 无匹配时会返回 `en` 而非开发语言，且不会把 `zh-Hant` 回退到 `zh-Hans`，因此不能直接使用其结果
- 兜底：`bootstrap(fallbackLanguage:)` 可配置，默认开发语言；Demo 使用 `en`

### 4.3 LocalizedBundle —— 运行时语言切换核心

```swift
/// Bundle.main 的私有子类，通过 object_setClass 替换 Bundle.main 的 isa
final class LocalizedBundle: Bundle {
    override func localizedString(forKey key: String, value: String?, table tableName: String?) -> String
    // 有覆盖语言 → 转发给 <lang>.lproj 子 bundle；否则走 super（系统默认行为）
}
```

要点：
- 只在首次 `setLanguage` / 启动时替换一次（`object_setClass` 幂等守卫）
- 当前语言 bundle 用 `OSAllocatedUnfairLock`（iOS 16+）/ `NSLock`（iOS 15）保护，保证多线程读取安全
- 覆盖范围：`NSLocalizedString`、`Bundle.localizedString`、`"key".localized()`、storyboard/xib 文案、`Bundle.main.preferredLocalizations`
- 实测：iOS 上 `String(localized:bundle:)` 走 Foundation 内部路径，**不经过**子类重写 → 提供 `Bundle.localized`（当前语言 `.lproj`），写法为 `String(localized: "key", bundle: .localized)`
- SwiftUI `Text(LocalizedStringKey)` 依赖环境 `\.locale` 选择语言，由 `.localizedRoot()` 注入（M3 验证）
- **不覆盖**：系统按钮/系统弹窗、`Info.plist` 文案、启动屏 —— 这些由系统按 `AppleLanguages` 决定（见 §6）

### 4.4 LocalizationStorage —— 持久化

| Key | 作用 |
| --- | --- |
| `wb.localization.language` | 用户在 App 内选择的语言代码；不存在表示跟随系统 |
| `AppleLanguages` | 选具体语言时写入 `[code]`，跟随系统时 `removeObject`。保证下次冷启动启动屏、App 名、权限弹窗、系统控件与 App 内语言一致 |

### 4.5 LocalizationManager —— 对外入口

```swift
@MainActor
public final class LocalizationManager: ObservableObject {
    public static let shared: LocalizationManager

    @Published public private(set) var language: AppLanguage   // 用户选择（可能是 .system）
    public var resolvedCode: String { get }                    // 实际生效的语言代码
    public var locale: Locale { get }
    public var isRightToLeft: Bool { get }
    public var availableLanguages: [AppLanguage] { get }

    /// App 启动时调用（didFinishLaunching 最早处）：恢复语言、替换 Bundle、设置全局布局方向
    public func bootstrap()

    /// 切换语言：更新 bundle → 持久化 → 清格式化缓存 → 更新布局方向 → 发通知
    public func setLanguage(_ language: AppLanguage)

    /// 打开系统设置中本 App 的页面（iOS 13+ per-app 语言入口）
    public func openSystemLanguageSettings()
}

public extension Notification.Name {
    static let wbLanguageDidChange: Notification.Name
}

public extension String {
    /// 便捷取值：支持格式化参数，自动走当前语言
    func localized(_ args: CVarArg..., table: String? = nil) -> String
}
```

### 4.6 LocalizedFormatters —— 格式化

| 方法 | 底层 | 示例（ar） |
| --- | --- | --- |
| `date(_:style:)` / `time` | `DateFormatter` + `setLocalizedDateFormatFromTemplate` | ١٩‏/١٠‏/٢٠٢٦ |
| `relative(_:)` | `RelativeDateTimeFormatter` | قبل ٣ ساعات |
| `number(_:)` / `percent(_:)` | `NumberFormatter` | ١٢٬٣٤٥٫٦٧ / ٤٥٪؜ |
| `currency(_:code:)` | `NumberFormatter.currency` | ‏١٢٣٫٤٥ US$ |
| `measurement(_:)` | `MeasurementFormatter` | 自动公制/英制 |
| `list(_:)` | `ListFormatter` | أ و ب و ج |
| `bytes(_:)` | `ByteCountFormatter` | — |

- Formatter 按 `locale.identifier + 配置` 缓存（创建成本高，列表滚动中频繁创建会掉帧）；收到语言变更通知时清空缓存
- 提供 `posixDateFormatter`（`en_US_POSIX` + 固定时区）专用于与服务端交互，**与展示用格式化严格分离**

### 4.7 UIKit 扩展

```swift
public extension UIApplication {
    /// 语言切换后调用：重设 semanticContentAttribute，并用 builder 重建各 window 的 rootViewController（交叉淡入）
    func relocalize(rootBuilder: @escaping (UIWindow) -> UIViewController)
}
public extension UIView {
    var isRightToLeft: Bool                               // effectiveUserInterfaceLayoutDirection
}
public extension UIImage {
    var directional: UIImage                              // imageFlippedForRightToLeftLayoutDirection()
}
```

全局方向：`UIView.appearance().semanticContentAttribute = isRTL ? .forceRightToLeft : .forceLeftToRight`，同时设置 `UINavigationBar/UITabBar/UISearchBar/UITableView` 等 appearance（部分系统控件不继承 UIView 的 appearance）。

### 4.8 SwiftUI 扩展

```swift
public extension View {
    /// 在根视图使用：注入 \.locale、\.layoutDirection，语言变化时以 .id 重建视图树
    func localizedRoot(_ manager: LocalizationManager = .shared) -> some View
}
```

### 4.9 Networking

```swift
public enum AcceptLanguage {
    /// 例："ar;q=1.0, en;q=0.9"，当前语言优先，追加系统偏好并去重
    public static func headerValue(_ manager: LocalizationManager = .shared) -> String
}
```

## 5. Demo App 设计

### 5.1 结构

- 入口：UIKit `AppDelegate + SceneDelegate`（便于语言切换时重建 rootVC）
- `RootTabBarController`：Tab 1「SwiftUI 示例」（`UIHostingController` + `.localizedRoot()`）、Tab 2「UIKit 示例」、Tab 3「设置」
- 语言切换后重建根控制器，保留当前 Tab 选中索引

### 5.2 L10n 类型安全 Key

```swift
enum L10n {
    enum Catalog {
        static var title: String { String(localized: "catalog.title") }   // 计算属性：每次取值都走当前语言
    }
    enum Plurals {
        static func files(_ count: Int) -> String { String(format: String(localized: "plurals.files"), count) }
    }
}
```

Key 命名：`<模块>.<页面/组件>.<语义>`，如 `rtl.progress.title`；每个 key 在 String Catalog 中写 `comment` 给译者说明上下文。

### 5.3 功能模块（每个模块 SwiftUI + UIKit 各一份）

| # | 模块 | 演示内容 | 重点语言 |
| --- | --- | --- | --- |
| 1 | BasicText | 静态文本、插值、位置参数 `%1$@ %2$@`（语序变化）、禁止拼接的反例对照 | ja, de |
| 2 | Plurals | 单变量复数、多变量复数（“N 个文件，M 个文件夹”）、0 的特殊文案 | ru, ar |
| 3 | Formatting | 日期/时间/相对时间、数字、货币、百分比、度量、列表、日本年号/伊斯兰历 | ar, ja, de |
| 4 | RTLLayout | leading/trailing、该镜像（箭头、返回、进度）与不该镜像（播放键、Logo、对勾、时钟）对照、横向滚动列表起点、动画/手势方向 | ar |
| 5 | LongText | 截断 vs 换行、按钮自适应宽度、空间不足时横排自动转竖排（`ViewThatFits` / `UIStackView` axis 切换）、Dynamic Type | de, ru |
| 6 | Typography | 中日汉字字形差异（同一字符在 zh/ja 下的字形）、阿拉伯字体行高、`lang` 属性对字体选择的影响 | ja, ar |

### 5.4 设置页

- 语言列表：「跟随系统」+ 6 种语言，每行显示原生名称 + 当前语言下的译名（如 `العربية — 阿拉伯语`）
- 当前生效语言 / Locale / 方向 信息展示
- 「前往系统设置修改语言」入口，并说明与 App 内切换的区别

## 6. 启动屏与系统级文案

| 项 | 方案 | 受 App 内切换影响？ |
| --- | --- | --- |
| 启动屏 | `LaunchScreen.storyboard`，文字由 xcstrings 本地化，图片用 Asset 语言变体，约束全部 leading/trailing | 下次冷启动生效（依赖 `AppleLanguages`） |
| App 名 | `InfoPlist.xcstrings` → `CFBundleDisplayName` | 由系统 per-app 语言决定 |
| 权限文案 | `InfoPlist.xcstrings` → `NS*UsageDescription` | 下次冷启动生效 |
| 系统控件（返回、取消、日期选择器） | `CFBundleAllowMixedLocalizations` 关闭，依赖 `AppleLanguages` | 下次冷启动生效 |

已知坑：启动屏有系统快照缓存，修改后需删除 App 或重启模拟器才能看到；文档中详述。

## 7. 测试策略

| 层级 | 内容 |
| --- | --- |
| 框架单元测试 | `LanguageResolver` 回退矩阵；`LocalizedBundle` 切换后取值正确；Storage 写入/清除 `AppleLanguages`；Formatter 各语言输出与缓存失效 |
| App 测试 | 解析 `Localizable.xcstrings`：每个 key 在 6 种语言均有 `translated` 状态；各语言格式占位符数量/类型一致；复数 key 覆盖 CLDR 要求的类别 |
| 手动 / 截图 | Scheme 启动参数 `-AppleLanguages (ar)`；Xcode 伪语言「Double-Length」「Right-to-Left」「Accented」 |

## 8. 适配指南大纲（Docs/iOS国际化适配指南.md）

1. 适配全景清单（Checklist）

11. 测试与 CI：启动参数、伪语言、截图测试、缺失翻译检查
12. 常见坑速查表（现象 → 原因 → 解决）

## 10. 验收标准

- `xcodebuild test` 框架与 App 测试全部通过；App 构建零警告
- 6 种语言冷启动 + App 内互相切换：文案、布局方向、格式化、复数全部正确，无需重启
- 阿语下所有页面正确镜像，不该镜像的元素保持不变；德语下无非预期截断
- 启动屏、App 名、权限文案在切换语言后的下一次冷启动与 App 内语言一致
- 框架可单独拷贝 `Packages/WBLocalizationKit` 接入其他项目使用
